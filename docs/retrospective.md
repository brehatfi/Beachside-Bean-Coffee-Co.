# Project Retrospective

## Project Title
**Beachside Bean Coffee Co. Website Project**

## Overview
This retrospective evaluates the process of planning and developing the Beachside Bean Coffee Co. website project. The goal of this reflection is to examine the project honestly, identify what contributed to success, recognize what created difficulty, and capture lessons that can improve future work.

Although the website itself was intentionally simple, the full assignment required more than technical execution. It required planning, discipline, consistency, and the ability to connect project management principles to a real deliverable. That made the process valuable because it highlighted how even a small project benefits from structure and reflection.

## What Went Well
One of the biggest strengths of this project was beginning with a defined scope. The scope statement created a clear foundation for the rest of the work. It identified the purpose of the website, the required deliverables, and the boundaries of the project. That made it easier to make decisions throughout the process because there was already a written guide for what the project was supposed to accomplish.

Another aspect that went well was the organization of the repository. Separating documentation into the `docs/` folder while keeping the website files in the root directory made the project easier to manage and more professional to review. That structure helped the project feel like one complete package rather than a collection of unrelated files.

The technical side of the project also benefited from staying simple. Limiting the website to two pages and one stylesheet made the work more manageable and allowed more attention to be given to clarity, readability, and consistency. Instead of trying to create a complicated website, the project focused on completing the required work well.

A final strength was the connection between the documentation and the website itself. Because the branding, purpose, and scope were defined early, it was easier to keep the writing and design aligned. That improved the overall cohesiveness of the final product.

## What Went Wrong
One challenge in this project was maintaining consistency across multiple files. Even in a small project, there are many details that must match, including business name, tone, file names, content, and design choices. Small inconsistencies can weaken the professionalism of the final product, so careful revision was necessary.

Another challenge was balancing planning with technical work. The website is the most visible part of the project, so it is easy to focus on that first. However, the documentation is just as important in this assignment because it demonstrates the project management process behind the final result. It took intentional effort to give equal attention to the scope, plan, retrospective, and technical files.

Time management was also a factor. Small website projects can seem simple at first, but details such as navigation, wording, formatting, and visual consistency take more time than expected. This project reinforced that even modest deliverables need a structured process if the final result is supposed to look polished.

## What I Would Do Differently
If I were completing this project again, I would begin by creating a master content guide for the project before drafting individual files. That guide would include the business name, tagline, tone, main descriptions, and visual direction. Having that reference earlier would reduce the chance of inconsistencies across documentation and website content.

I would also create a more detailed personal checklist tied directly to the grading rubric. The rubric identifies what separates strong work from incomplete work, so using it more actively during the project would make it easier to catch weaknesses before the end.

Another improvement would be to schedule a final review session focused only on professionalism. During that review, I would examine the repository as if it were a portfolio piece rather than a class assignment. That perspective would help improve wording, formatting, and overall presentation.

Finally, I would build in more time for revision. The first version of a file is rarely the strongest version. Allowing more time for reflection and cleanup would strengthen both the technical work and the documentation.

## Lessons Learned
This project reinforced the importance of scope, planning, and accountability. A clear scope reduces confusion. A written plan makes the work more manageable. Reflection reveals what can be improved. Together, these steps create a stronger process and a better final product.

The project also showed that professionalism is built through consistency. A repository becomes more effective when all parts feel connected, intentional, and complete. That includes naming, organization, writing quality, and visual design.

Most importantly, this project demonstrated that project management is not separate from execution. The planning documents were not just supporting materials; they shaped the quality of the final website. The project worked best when planning and building were treated as connected parts of the same process.

## Final Reflection
Overall, this project was a useful example of how a small digital project can benefit from structured management. It provided practical experience in moving from concept to delivery while staying within clear limits. The final result is not only a simple website prototype, but also evidence of planning, problem-solving, and reflection.

That combination is what makes the project valuable. It shows that successful work is not only about finishing a product, but also about managing the process with intention.
