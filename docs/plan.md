# Project Plan

## Project Title
**Beachside Bean Coffee Co. Website Project**

## Project Summary
This project plan outlines the work required to complete the Beachside Bean Coffee Co. website project. The final deliverable is a two-page website prototype supported by a full set of project management documents housed in one public GitHub repository. The project is designed to demonstrate how a small digital project can be managed from conception to completion through scope definition, planning, risk awareness, execution, and reflection.

This plan is intentionally practical. Because the project is being completed by one student, the focus is on maintaining a realistic workload, organizing the work clearly, and completing each deliverable with consistency and professionalism.

## Project Goals
The primary goals of this project are to:

- complete all required files for the final project
- maintain alignment with the approved project scope
- create a website that is functional, readable, and visually consistent
- demonstrate the use of project management principles in planning and execution
- present the final repository as a polished and professional portfolio piece

## Project Strategy
The work for this project will be completed in deliberate stages. Documentation will be completed early so that the project has a clear direction before development begins. Website content and structure will then be drafted before styling is finalized. The project will conclude with testing, reflection, and final repository review.

This approach supports accountability because it reduces the chance of rushing the work at the end. It also reflects the course emphasis on planning before execution and evaluating the process after delivery.

## TAME Risk Analysis

The TAME framework identifies project risks in four areas: Technical, Assumptions, Market, and Execution.

### Technical Risks
Technical risks involve problems that may affect the functionality or quality of the website.

- Limited experience with HTML and CSS may lead to layout or formatting issues.
- Navigation links could break if file names or paths are inconsistent.
- Styling may appear inconsistent between pages if the CSS is not reviewed carefully.
- Small code errors may reduce the overall professionalism of the website.

**Response Strategy:**  
Use a simple site structure, test both pages carefully, keep the CSS in one shared file, and review the site in a browser after each major revision.

### Assumption Risks
Assumption risks relate to expectations that may not hold true if the project changes.

- The project assumes that a two-page informational website is sufficient to meet all assignment requirements.
- The project assumes that GitHub Pages will publish the site successfully.
- The project assumes that the fictional business concept will remain stable and not require significant rebranding or restructuring later.

**Response Strategy:**  
Review the assignment instructions and rubric frequently, keep the scope narrow, and avoid adding features that are not required.

### Market Risks
In this academic project, “market” risks refer to how effectively the website communicates its purpose to the intended audience.

- The fictional coffee shop could feel too generic without a clear identity.
- The website may not feel engaging if the written content is too vague or repetitive.
- If the business theme is not reflected visually, the website may appear disconnected from its own purpose.

**Response Strategy:**  
Use a clear coastal coffee shop identity, keep the writing specific and brand-focused, and apply a visual style that supports the business concept.

### Execution Risks
Execution risks involve the ability to complete the project on time and with sufficient quality.

- Time management may become a problem if documentation and coding are delayed.
- The website could receive too much attention compared to the written documents.
- Last-minute revisions may create inconsistencies across files.
- Small details such as naming, links, or formatting may be overlooked near submission.

**Response Strategy:**  
Complete the project in phases, check each deliverable against the rubric, and leave time at the end for final review and revision.

## Work Breakdown Structure (WBS)

### Phase 1: Repository Setup
1. Create public GitHub repository
2. Add required root files:
   - `README.md`
   - `index.html`
   - `about.html`
   - `style.css`
3. Create `docs/` folder
4. Add required documentation files:
   - `scope.md`
   - `plan.md`
   - `retrospective.md`

### Phase 2: Scope and Planning
1. Review and revise the scope statement
2. Confirm project boundaries and deliverables
3. Write the project plan
4. Identify risks using the TAME framework
5. Build a simple task schedule

### Phase 3: Website Content Development
1. Draft homepage content
2. Draft about page content
3. Decide on page structure and section headings
4. Establish business tone and branding language

### Phase 4: Website Build
1. Create `index.html`
2. Create `about.html`
3. Add semantic page structure
4. Add navigation between pages
5. Write shared CSS styles
6. Review layout, spacing, and readability

### Phase 5: Testing and Quality Review
1. Test all navigation links
2. Review spelling and grammar
3. Confirm consistent branding and naming
4. Check file organization
5. Review project against assignment rubric

### Phase 6: Reflection and Delivery
1. Write `retrospective.md`
2. Publish website to GitHub Pages
3. Add live link to `README.md`
4. Perform final repository review
5. Submit final project

## Roles and Responsibilities
This project is being completed individually, so all major responsibilities are assigned to the student project manager/developer. These responsibilities include:

- defining the scope
- planning deliverables and deadlines
- identifying and responding to risks
- writing project documentation
- building the website prototype
- testing and revising the final product
- reviewing the finished repository for professionalism and completeness

## Quality Standards
The project will be considered high quality if it meets the following standards:

- all required files are present and correctly organized
- the website includes two working, linked pages
- the CSS provides a consistent visual design
- the content is clear, readable, and appropriate for a fictional small business
- the documentation demonstrates understanding of course concepts
- the repository presents the project as a cohesive and professional whole

## Final Planning Reflection
This plan is successful if it helps maintain focus, prevent scope creep, and create a steady path from idea to delivery. The goal is not just to finish the project, but to finish it in a way that clearly reflects thoughtful planning, accountability, and professionalism.
